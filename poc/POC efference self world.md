# Project Arche — Proof of Concept

### Efference Copy Self/World Discrimination

**v0.1 — June 2026**
*Companion to Architecture Specification v4.6 and Research Hypothesis Document v1.2*

-----

## Purpose

This document specifies the first implementation milestone for Project Arche: a minimal, falsifiable proof of concept that isolates the architecture’s foundational bet — that the self/world boundary, generated by efference copy, is what makes grounded concept formation possible. The POC tests **Primary Hypothesis 3** (efference copy as prerequisite) at the smallest scale at which the claim is meaningful.

The POC is deliberately scoped below the full architecture. It is not Genesis phase. It does not use the Genesis physics engine, the humanoid body, vision, audition, the memory systems, or the full registry. It implements one mechanism and the minimum scaffolding required to observe whether that mechanism does what the architecture claims. The goal is empirical: to move the project from implementation-zero to a first result that either supports or pressures the foundational hypothesis, and to do so in weeks rather than months.

> **Founding-principle note.** This POC honors the core commitments: no reward function, no backpropagation, no global error signal, no pretrained representations, no pre-seeded structure. Learning proceeds via local plasticity, and self/world attribution emerges from consistency rather than being labeled. Where the POC departs from the full architecture, it does so by omission (fewer channels, simpler body, smaller world), never by violating a founding commitment.

-----

## What the POC Tests

The distinguishing claim of Arche is not prediction error, embodiment, or Hebbian learning in isolation — each of those appears in comparator systems. The claim that no comparator demonstrates is that **efference copy can generate a self/world boundary from physics alone, with no labels, and that this boundary is the prerequisite for coherent concept formation.** Monty performs sensorimotor learning but does not tag motor output with a paired predictive signal; it cannot architecturally distinguish self-caused from world-caused prediction error. That gap is the ground the POC stands on.

**Hypothesis under test (Primary Hypothesis 3).** A system that pairs every motor command with an efference-copy prediction will, over runtime, separate self-caused prediction errors from world-caused prediction errors — without being told which is which.

**Falsification.** If the forward model learns to predict well (prediction error falls) but the self-caused and world-caused error distributions never separate, the claim that efference-copy consistency is sufficient to generate the boundary is under direct pressure. That is the result worth having, success or failure.

## Scope

### In scope

- A 2D physics world (Pymunk — native 2D, honest continuous contact forces, no GPU dependency).
- A minimal articulated body: a two-link arm anchored at a base, driven by two joint motors, constrained to the plane.
- A minimal world to act on: one pushable block (movable — world Arche can affect) and one fixed wall (immovable — world Arche cannot affect). Together with the arm’s own motion (self), these give three categories of consequence to be separated.
- One to two sensory channels: proprioception (joint angles and angular velocities) and contact-force magnitude. No vision, no audition.
- The core loop: sensory read → forward-model prediction (efference-copy paired) → prediction error → self/world tag → local plasticity update → read-only log.
- A read-only logger — the registry in embryo — recording per-step state, prediction, error, and tag, with no path back into the cognitive code.
- A single diagnostic output: the separation (or non-separation) of self-caused and world-caused error distributions over runtime.

### Out of scope

- Genesis, the humanoid body, URDF sourcing, Luisa/Vulkan rendering, ROCm — all deferred to Genesis phase.
- Vision and audition channels.
- The three-system memory architecture, consolidation gating, decay, and pruning. (Episodic memory, trace resolution, and reconstructive retrieval are a parked design question — see [Deferred Questions](#deferred-questions).)
- The internal-state dimensions as load-bearing modulators. Arousal may be logged but is not yet wired to gate anything.
- Concept formation, goal maintenance, language, and the neurological simulation application.
- The full four-layer registry. Only the read-only logging discipline is preserved.

## Architecture of the POC

### The clean boundary (non-negotiable)

The single structural discipline that keeps this POC from being throwaway is a clean world interface. The cognitive code never imports the physics engine. A `World` class exposes exactly three methods —

```python
class World:
    def step(self, dt): ...
    def apply_motor(self, commands): ...
    def read_sensors(self): ...
```

— and Pymunk lives entirely behind it. When the project moves to Genesis, only this one class is reimplemented; the forward model, the prediction-error computation, the self/world tagger, the plasticity update, and the logger all carry over untouched. **The physics layer is expected to be replaced; the cognitive layer is not.**

### Cognitive components

**Forward model.** Given the current sensory state and the motor command about to be issued, predict the next sensory state. The motor command is the efference copy — it is what makes the prediction aware of the system’s own action. Initial form may be a linear map or a small two-layer network; the form matters less than the learning rule.

**Prediction error.** Observed next state minus predicted next state, per channel. This is the only learning signal.

**Self/world tagger.** The claim itself. When the efference-informed prediction matches observation, the residual is self-attributable — the system’s own action explained the outcome. When a large residual is present that the efference copy did not anticipate, it is world-attributable. The *consistency* of this relationship across time is what sorts events into self versus world; nothing is hardcoded as one or the other.

**Local plasticity update.** The forward model improves through a local Hebbian rule, not backpropagation. This is the most demanding component and the one that carries the no-backprop bet at small scale. The convenient path — an autograd loss and a backward pass — is precisely what is disallowed.

**Read-only logger.** Each step appends `sim_time`, motor command, predicted state, observed state, per-channel error, and the self/world tag. It writes outward only (in-memory list or CSV) and has no path back into the cognitive code. This is the registry’s isolation constraint in miniature, and building the habit now is deliberate.

## Build Sequence

Ordered by dependency, the same discipline the Eden build order follows. Each step rests on the one before it.

1. **Physics spike.** Stand the arm up in Pymunk. Drive the two motors. Confirm the block pushes and the wall resists. Read continuous contact forces and confirm they are clean enough at the required time resolution. No cognition yet. **This is the real risk** — the same contact-force-access risk that would appear in Genesis, surfaced cheaply on day one.
1. **Wrap the World interface.** Put `step` / `apply_motor` / `read_sensors` around the Pymunk world. From here forward, no cognitive code touches Pymunk.
1. **Forward model and prediction error, logging only.** Predict the next sensory state and log the raw error. Do not tag yet. Develop a feel for the signal: what error looks like during free motion versus during contact.
1. **Add efference copy and the self/world tagger.** Pair the motor command into the prediction and begin sorting errors into self versus world by consistency. Log the tag alongside the error.
1. **Swap learning to the local Hebbian rule.** Replace any provisional optimizer with the local plasticity update. This is where the central architectural uncertainty lives and where time is most likely to be spent.
1. **Run long, produce the diagnostic.** Run to sufficient runtime and produce the error-distribution plot. Read the result against the failure tiers below.

## Result and Diagnostic

The primary output is one plot: runtime on the x-axis, the self-caused and world-caused error distributions shown separating (or failing to) over time. A second optional view plots self/world classification accuracy against ground truth — which the simulation knows even though the system does not.

The logger does more than report success; it diagnoses the *kind* of failure, which is what makes failing early useful rather than discouraging:

|Observation                                              |Failure tier        |Meaning                                                                                                                                                                                              |
|---------------------------------------------------------|--------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
|Prediction error stays high everywhere                   |**Learning failure**|The forward model isn’t predicting. Points at the local plasticity rule, not the boundary claim. Weak evidence against the no-backprop bet, since only one rule among many was tried.                |
|Prediction error falls but the self/world tag never sorts|**Boundary failure**|The expensive, interesting result: prediction works yet efference-copy consistency does not generate the self/world distinction. This is the tier that puts genuine pressure on Primary Hypothesis 3.|

**Failure discipline.** Locate the failure tier before adjusting. A physics-engine or channel mismatch (the cheapest tier) earns a one-line fix, not an architecture conversation. Only a boundary failure — prediction working, tagging not — earns a revision of the architectural claim. The trap is responding to a cheap failure with an expensive change.

## Learning Value

Every component of the POC is on the critical path to the full build; nothing is throwaway except the physics layer, which is expected to be replaced behind the `World` interface. The POC teaches the Pymunk/physics workflow, the core-loop skeleton reused at full scale, a Hebbian update expressed in tensors, and the read-only-logger discipline that becomes the registry. It is concurrently the first concrete Python milestone and the first falsifiable architectural result.

## Deferred Questions

Raised during POC planning and deliberately parked. Recorded here so they are not lost.

- **Memory time-depth and resolution.** How much time is retained, how much information within that time, and how memories behave across time. The architecture handles memory *dynamics* (consolidation, decay, pruning) and memory *variation* (the neuromodulatory parameters double as a theory of inter-individual memory difference) well, but two questions are genuinely under-specified: episodic trace resolution (full vector versus compressed signature — the registry’s waveform-hash instinct suggests compression) and retrieval mechanism (reconstructive partial-cue completion versus playback). Best revisited after episodic memory exists and there is real trace data to reason against, not in the abstract.
- **Minimal hook to preserve now.** When logging traces in any future episodic build, record arousal-at-encoding alongside the trace even before it is used. It costs nothing and preserves the encoding signal the variation theory depends on. Not required for this POC.
